# 项目管理器 Electron 架构重构计划

## 一、现状问题

### 1.1 目录结构混乱

```
现状 services/                          现状 handlers/
  (flat files + some dirs)               (all flat files)
  build-tool/         ← npm 专属          context.ts
  port-config/        ← npm 专属          port-config.handler.ts
  project-type/                          process.handler.ts    ← 混了 process:* + projectMgr:*
  proxy-config/       ← npm 专属          project.handler.ts    ← 混了 project:* + source:*
  vcs/                                   proxy.handler.ts
  data-dir.service.ts                    settings.handler.ts   ← 混了 settings:* + update:*
  notification.service.ts                system.handler.ts
  process-manager.service.ts             task.handler.ts        ← 混了 task:* + notification:*
  project.service.ts                     vcs.handler.ts
  project-repository.service.ts
  settings.service.ts
  source-manager.service.ts
  store.service.ts
  task.service.ts
  tool-discovery.service.ts
  update.service.ts
```

问题：
- npm 专属的 `build-tool/` / `proxy-config/` / `port-config/` 与通用服务平级
- `project-type/providers/maven/index.ts` 单文件塞满所有 Maven 逻辑（检测+命令+多模块+框架）
- 无 Gradle / pnpm / yarn 支持
- handlers 层是纯透传（`ipcMain.handle('x', ()=>service.method())`），无任何业务价值
- preload.ts 258 行，全是 `args => ipcRenderer.invoke('channel', args)` 式一对一 wrapper
- `ProjectService` 含 Tomcat 硬编码（catalina.bat / webapps / WAR 路径）
- `Project` 接口含 `javaHome/mavenHome/tomcatHome/tomcatWarName` Java 专属字段

| 位置 | 硬编码内容 |

| `project-type/providers/maven/index.ts:14-18` | `start/build/install/runScript/cleanDirs` 全部写死字符串 |

### 3.2 preload.ts — 压缩为通用桥接

**现状**：258 行，10 个 API 分组，每个函数都是 `args => ipcRenderer.invoke('channel', args)`。

**改造后**：~15 行，暴露通用 `invoke` 和 `on` 方法。

```ts
// preload.ts
import { contextBridge, ipcRenderer } from 'electron'

contextBridge.exposeInMainWorld('electronAPI', {
  invoke: (channel: string, ...args: unknown[]) => ipcRenderer.invoke(channel, ...args),
  on: (channel: string, callback: (...args: unknown[]) => void) => {
    const handler = (_e: Electron.IpcRendererEvent, ...data: unknown[]) => callback(...data)
    ipcRenderer.on(channel, handler)
    return () => ipcRenderer.removeListener(channel, handler)
  },
})
```

**前端调用变更**（需全局搜索替换）：

| 现状 | 改造后 |
|---|---|
| `window.electronAPI.startProject(idx)` | `window.electronAPI.invoke('process:start', idx)` |
| `window.electronAPI.loadProjects(path)` | `window.electronAPI.invoke('project:load', path)` |
| `window.electronAPI.vcsUpdate(idx)` | `window.electronAPI.invoke('vcs:update', idx)` |
| `window.electronAPI.getSetting(key)` | `window.electronAPI.invoke('settings:get', key)` |
| `window.electronAPI.setSetting(key, val)` | `window.electronAPI.invoke('settings:set', key, val)` |
| `window.electronAPI.onOutputBatch(cb)` | `window.electronAPI.on('event:outputBatch', cb)` |
| `window.electronAPI.onProjectStarted(cb)` | `window.electronAPI.on('event:projectStarted', cb)` |

**影响范围**：
- `src/types/ipc.ts` — `IpcApi` 接口重写为通用接口
- `src/` 下所有 `window.electronAPI.xxx(...)` 调用 → `window.electronAPI.invoke('channel', ...)`
- `src/` 下所有 `window.electronAPI.onXxx(cb)` → `window.electronAPI.on('event:xxx', cb)`
- `src/composables/useModal.ts` — 如依赖 electronAPI 需同步改

### 3.3 services/core/ — 基础设施层

**现状**：`settings.service.ts` / `store.service.ts` / `data-dir.service.ts` 散落在顶级。

**改造**：
- 移入 `services/core/` 目录
- 功能不变，只改 import 路径

文件详情：

#### `services/core/settings.service.ts`
- **来源**：`services/settings.service.ts`
- **功能**：`AppSettings` 类，JSON 嵌套 key 读写（`get/set/delete/has/getAll`），schema 驱动的默认值
- **对外接口**：`new AppSettings(settingsPath, schemaPath)` → `get(key, default?)` / `set(key, value)` / `delete(key)` / `has(key)` / `getAll()` / `getSchema()`
- **依赖**：无（纯 Node fs 操作）
- **改动**：无，仅移动路径

#### `services/core/store.service.ts`
- **来源**：`services/store.service.ts`
- **功能**：通用 KV 存储，每个 key 一个独立 JSON 文件
- **对外接口**：`createStore(dataDir)` / `storeGet(store, key)` / `storeSet(store, key, value)` / `storeDelete(store, key)` / `storeKeys(store)`
- **依赖**：无

```ts
export interface RunnableModule {
  name: string
  modulePath: string
  framework: 'spring-boot' | 'tomcat' | null
}

export function detectRunnableModules(rootPath: string): RunnableModule[] {
  // 1. 读取根 pom.xml
  // 2. 若 <packaging> != 'pom' 或无 <modules> → 返回空（单模块，不弹窗）
  // 3. 遍历每个 <module>：
  //    a. 检查子模块 pom 是否含 spring-boot-maven-plugin → framework = 'spring-boot'
  //    b. 若子模块也是 <packaging>pom</packaging> + 有 <modules> → 递归
  // 4. 过滤掉无 framework 的模块（如 domain/common）
  // 5. 返回 RunnableModule[]
}
```

**`start.ts` 核心逻辑**：

```ts
export function resolveStartCommand(rootPath: string, module?: RunnableModule): string {
  if (module) {
    return `mvn spring-boot:run -pl ${module.modulePath}`
  }
  // 单模块 Maven 项目
  return 'mvn spring-boot:run'
}
```

### 3.9 `Project` 接口通用化

**现状**（`src/types/project.ts`）：

```ts
export interface Project {
  name: string
  path: string
  projectType: string
  javaHome: string        // Java 专属
  mavenHome: string       // Java 专属
  tomcatHome: string      // Java 专属
  tomcatWarName: string   // Java 专属
}
```

**改造后**：

```ts
export interface Project {
  name: string
  path: string
  projectType: string
  toolEnv: Record<string, string>  // { JAVA_HOME, MAVEN_HOME, GRADLE_HOME, CATALINA_HOME, ... }
}
```

- `toolEnv` 中的 key 由各 project-type provider 自行约定
- Maven provider 读 `toolEnv.JAVA_HOME` / `toolEnv.MAVEN_HOME`
- Gradle provider 读 `toolEnv.JAVA_HOME` / `toolEnv.GRADLE_HOME`
- 将来加 Python：`toolEnv.PYTHON_HOME` / `toolEnv.VENV_PATH`
- 将来加 Go：`toolEnv.GOPATH` / `toolEnv.GOROOT`

**迁移**：`projects.json` 中的旧格式需自动转换：

```ts
// 在 ProjectRepository.load() 或 ProjectService 初始化时
function migrateProject(p: any): Project {
  if (!p.toolEnv) {
    p.toolEnv = {}
    if (p.javaHome) p.toolEnv.JAVA_HOME = p.javaHome
    if (p.mavenHome) p.toolEnv.MAVEN_HOME = p.mavenHome
    if (p.tomcatHome) p.toolEnv.CATALINA_HOME = p.tomcatHome
    // 删除旧字段
    delete p.javaHome
    delete p.mavenHome
    delete p.tomcatHome
    delete p.tomcatWarName
  }
  return p
}
```
